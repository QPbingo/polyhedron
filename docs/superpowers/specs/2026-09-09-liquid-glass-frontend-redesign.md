# 多面体 Liquid Glass 前端重构设计

## 状态

本设计已通过五轮可交互 HTML Demo 收敛。用户确认视觉方向、双栏布局、项目级操作和原生终端输入模型后，要求将其应用到正式 React 前端。

## 目标

将正式前端重构为基于 Name That UI 组件分类与 Liquid Glass 设计语言的 Agent 工作台，同时保持现有业务能力、传输协议和安全边界不变。

本轮成功标准：

- 桌面端始终以左侧项目导航、右侧终端为主结构。
- Liquid Glass 只用于浮动导航、工具栏、按钮和临时操作层；终端、项目内容与信息正文保持不透明、高对比。
- 添加项目位于 `Projects` 标题行右侧。
- 新建会话和项目设置属于具体项目，仅在项目悬浮、键盘聚焦或触控环境中显示。
- 用户直接在 xterm 会话区域输入，不增加聊天式输入框。
- 全部现有功能与错误、加载、离线和空状态继续工作。
- 单元测试、构建、浏览器回归与真实开发模式冒烟检查通过后才允许推送。

## 非目标

- 不改变 Relay、Host、Connector、数据库或 WebSocket 协议。
- 不迁移 React、Vite、xterm 或测试框架。
- 不把 Name That UI 当作 npm 组件包。该网站是组件与风格图鉴；实现采用其组件语义和 Liquid Glass 规则，不复制站点源码。
- 不在终端内容层铺设玻璃、渐变或装饰性蒙层，以免影响 ANSI 颜色和文字可读性。

## 已确认的界面结构

### 顶部控制层

页面顶部使用浮动玻璃工具栏，包含品牌、当前项目/会话面包屑、本机连接状态、专注模式、设置和账号标识。工具栏使用镜片式边缘高光、动态染色和同心圆角，但不承载长正文。

### 左侧项目导航

左栏是独立不透明内容面板，包含：

1. 搜索框和 `Cmd/Ctrl+K` 快捷键。
2. 全部、待处理、已结束筛选分段控件。
3. `Projects` 标题、项目数和标题右侧的添加项目按钮。
4. 可折叠项目树及其会话。
5. 项目行的项目级操作：新建会话、项目设置。

项目级操作在悬浮和 `focus-within` 时渐显；不支持悬浮的设备始终显示。新建会话入口接收明确的 `Project` 对象，继续通过 `projectId` 和 `hostId` 创建，不能退化为全局新建入口。

### 右侧终端工作区

终端占据除左栏以外的全部可用空间。顶部保留会话 Agent、连接状态、会话详情、刷新、终端搜索、复制和专注模式操作。主体继续使用现有 `TerminalView` 和 xterm，用户点击终端后直接输入原生 CLI。

不存在额外的消息输入框、发送按钮或输入代理层。现有二进制 WebSocket 输入、粘贴、快捷键、权限审批和终端尺寸协商保持不变。

### 会话详情

会话详情不再作为第三栏参与主网格布局。点击工具栏详情按钮时，它从右侧以临时检查器浮出；关闭后终端立即恢复无遮挡状态。

详情继续提供主机、项目、状态、操作权、接管、中断、终止、重命名、历史、恢复和归档能力。破坏性操作继续使用确认对话框。

### 对话框与设置

添加项目、新建会话、项目设置、设置、帮助、历史与确认流程保留现有数据和验证逻辑，视觉统一为临时玻璃控制层。表单正文采用近乎不透明的深色表面，确保输入和说明文字对比度稳定。

现有六套配色键保持兼容，重绘为六组深色环境光主题，避免破坏已保存的 `localStorage` 偏好和查询参数。终端调色板同步更新，但仍保证 ANSI 基础色可辨识。

## 组件标准化

`App` 只负责认证、数据订阅、顶层状态和业务命令协调。视觉与交互拆为以下边界：

- `ui/Icon`：统一图标表、尺寸和描边规范。
- `ui/GlassButton` / `ui/ToolButton`：玻璃按钮、按压、禁用和焦点状态。
- `ShellHeader`：品牌、面包屑、连接状态和全局工具。
- `Sidebar`：搜索、筛选、项目树和项目级操作。
- `Workspace`：终端工具栏、`TerminalView`、空状态和详情检查器。
- `SessionDetails`：会话事实与会话动作。
- `Modal` / `Field`：对话框和表单基础组件。

现有 `ProjectForm`、`ProjectActions` 和 `TerminalView` 的业务逻辑保留；可调整 DOM 结构和样式接口，但不改变后端请求合同。

## 设计系统

### 色彩与表面

- 页面底色：带蓝色环境光的近黑背景。
- 内容面板：不透明深蓝黑，弱分隔线，无大面积透明正文。
- 玻璃控件：`backdrop-filter: blur(...) saturate(...)`、半透明染色、内外高光和细边界。
- 主动作：冷白到蓝紫的实心镜片渐变。
- 状态色：绿色运行、黄色等待、红色危险、灰色结束；不随主题改变含义。

### 几何与排版

- 控制组使用胶囊与同心圆角；内容面板使用 20–24px 外圆角。
- 字体使用本地 `Geist`/系统字体回退，不增加远程字体依赖。
- 终端继续使用系统等宽字体和用户设置的 12–20px 字号。
- 数值、路径和会话 ID 使用等宽或 tabular figures。

### 动效

- 工具悬浮、项目操作显隐、详情检查器和对话框使用 180–450ms 的弹性缓动。
- 不使用会改变布局的 `top/left/width/height` 动画。
- `prefers-reduced-motion` 关闭非必要动画。
- `prefers-reduced-transparency` 使用近乎不透明的回退表面。

## 响应式行为

- 宽桌面：270px 左栏 + 自适应终端。
- 紧凑桌面与 Codex 内置浏览器：220–240px 左栏 + 自适应终端，仍保持左右双栏。
- 仅在小于约 580px 的手机宽度切为上下结构。
- 会话详情始终覆盖于终端之上，不创建第三个固定网格列。
- 专注模式隐藏左栏和顶部非必要信息，终端占满视口。

## 可访问性与状态

- 所有图标按钮包含可读名称、标题和清晰的 `focus-visible`。
- 悬浮出现的项目动作也可通过键盘 `focus-within` 和触控设备访问。
- 对话框继续使用原生 `<dialog>` 的焦点与 Escape 行为。
- 连接、加载、空列表、无主机、离线、错误、冲突、忙碌和历史截断状态全部保留。
- 状态信息不只依赖颜色，继续显示文字标签。

## 实现策略

1. 先提取无业务副作用的图标、按钮、布局和详情组件。
2. 将现有 `App` 业务回调按原签名传给新组件，保持请求和订阅逻辑不变。
3. 重写 `styles.css` 和 `palettes.css` 为 token 驱动的 Liquid Glass 设计系统。
4. 更新登录、设置、帮助、项目、新建会话、历史和确认状态。
5. 在每个拆分阶段运行类型检查和单元测试，最后执行完整浏览器回归。

## 验证计划

- `npm run test:unit`
- `npm run typecheck`
- `npm run build`
- Playwright 工作区测试：登录、项目折叠、项目级新建、项目设置、筛选、搜索、会话选择、详情、接管、审批、断线、设置、历史、专注模式。
- 视口检查：1440×900、1237×745、736×863、580px 临界值与 390px 手机兜底。
- 浏览器控制台不得出现错误或未处理 Promise。
- 手动确认 xterm 仍是唯一输入面，终端尺寸和直接键盘输入未被玻璃层阻挡。

## 推送条件

只有在工作树差异检查、全部自动化检查和本机浏览器冒烟通过后，才提交实现并推送当前 `main` 到 `origin/main`。任何无法在本机验证的外部 OIDC、跨设备或生产 TLS 条件必须如实记录，不宣称已通过。
