# Agent 终端工作台 V1 方案

日期：2026-09-08

状态：初版设计，待评审；不是已实现或已验证的产品能力。

方法：按 brainstorming 收敛既定技术方向，使用 OpenAI Docs 核对 Codex 的 Hook 与恢复接口。

## 1. 产品目标与边界

用户在本地 Mac 安装并绑定一次运行服务后，可以在不同 PC 的浏览器登录同一个产品账号，查看、操作同一个 Codex 或 Claude Code 会话。Agent 进程、项目文件和厂商登录凭据始终留在原执行主机；切换控制端不迁移执行环境，也不复制或新建 Agent。

V1 使用真正的交互式 CLI 终端，不使用聊天消息重绘替代终端，不依赖 Codex App Server 或 Claude Agent SDK 重写 Agent 循环。

| 项目 | V1 范围 |
| --- | --- |
| 执行主机 | Apple Silicon Mac，本地当前用户权限 |
| 控制端 | macOS 的 Chrome/Safari、Windows 的 Chrome/Edge 为首发验收范围；其他浏览器不作首发承诺 |
| Agent | Codex CLI、Claude Code；发布经过测试的兼容版本清单 |
| 会话来源 | 只管理本产品启动的会话 |
| 账号 | 个人账号；同一账号可绑定多个执行主机，每个会话固定归属一台主机 |
| 同时访问 | 多端查看、单端操作；不同会话可以由不同 PC 操作 |
| 会话恢复 | 活进程重连 + 厂商历史会话恢复；二者在 UI 中明确区分 |
| 人工审批 | Hook 提醒，用户在原始 CLI 审批界面操作 |

不包含：移动端适配、原生桌面工作台、团队协作、跨账号分享、主机间任务迁移、自动恢复执行任务、第三方 Agent、全功能文件编辑器、文件上传下载、Git worktree 自动隔离、任意已有终端接管、聊天模式、P2P 直连与离线控制。

本地安装包仅安装后台运行服务及设置/诊断入口，不代表开发一套桌面主界面。模型请求可以访问厂商云服务，“本地运行”指 Agent 和工具执行位置，并不意味着模型离线推理。

## 2. 用户主流程

### 2.1 首次准备

1. 用户在 PC 浏览器注册或登录产品账号。
2. 在执行 Mac 下载经过签名与公证的安装包，安装当前用户级后台服务。
3. 服务生成主机密钥，发起短时、单次使用的绑定请求，打开浏览器确认账号和主机名称。
4. 云端把主机身份绑定到该账号；主机凭据存入 macOS Keychain。
5. 设置页检测 Codex/Claude Code 的安装路径、版本和可用性；未安装或未登录时提供明确指引，不静默安装 CLI 或复制凭据。
6. 用户在执行 Mac 首次授权可用于新建会话的项目根目录。

产品账号只授权远程访问。Codex/Claude Code 自身的登录、订阅、API Key 和权限政策保持独立，初次登录按厂商原生流程在执行 Mac 完成。

### 2.2 创建与操作会话

1. 点击“新建会话”，选择在线主机、已授权目录、Agent；记住上次选择。
2. 主机复核目录和 Agent 版本，建立会话记录与 PTY，启动原生交互式 CLI。
3. 注入仅对受管会话生效的 Hook 桥接，记录厂商原生会话 ID。
4. 创建者获得操作权，终端自动聚焦。
5. 用户使用原有命令、补全、菜单、输入法与快捷键。业务层不尝试把键盘字符解释成对话消息。

同目录启动第二个会话时提示文件修改冲突风险；V1 不保证两个 Agent 修改相同文件的隔离性。

### 2.3 跨 PC 继续

1. PC B 登录同账号，即可看到主机和会话列表，不安装本地运行服务。
2. 打开会话，先恢复屏幕并进入查看态。
3. 点击“在此设备继续”，主机授予新的操作权版本。
4. PC A 转为查看态并显示当前操作端；其旧版本输入被主机拒绝。
5. PC B 完成屏幕同步与尺寸确认后才启用输入。接管本身不终止 Agent、不新建原生会话。

无需逐条指令确认操作权。所有已登录控制端均受账号授权约束，账号和客户端撤销规则见第 8 节。

## 3. 界面范围

只做三个主要页面：登录页、设备/环境设置页、会话工作台。

工作台组成：

- 左侧：按执行主机分组的会话列表，展示 Agent、名称、状态和未读完成提醒。
- 顶部：项目目录、连接状态、Agent 状态、当前操作端与“在此设备继续”。
- 主区域：单个活动 xterm.js 终端；V1 不做分屏。
- 菜单：新建、重命名、查找、复制、历史记录、中断、结束进程、恢复历史、归档。

关闭页面/标签只断开查看；“中断”使用当前 CLI 的中断语义；“结束进程”需确认并终止本产品持有的进程树。结束与归档都不删除厂商原生历史。

长会话的活动终端只保留有界回滚区。更早输出在独立只读历史查看入口分段加载，不把旧字节重新写入当前活动终端。终端中的查找明确限于已加载回滚区，不冒充全历史搜索。

## 4. 技术架构

```text
PC A 浏览器 ─┐
            ├─ HTTPS / WSS ─ 云端账号服务 + 中继 ─ 出站 WSS ─ 本地连接服务
PC B 浏览器 ─┘                                                │
                                                             │ 本地认证 IPC
                                                   PTY Session Host
                                                   ├─ Codex / Claude Code PTY
                                                   ├─ 权威终端状态
                                                   ├─ 操作权与输入队列
                                                   ├─ Hook 接收与状态投影
                                                   └─ 本地元数据、快照、日志
```

本地 Session Host 是会话的权威执行者。云端在线状态和会话列表是投影，不能因为云端记录消失就认为本地 Agent 已退出。

### 4.1 技术选择

| 模块 | 选择 |
| --- | --- |
| Web | React、TypeScript、Vite |
| 终端 | @xterm/xterm + @xterm/addon-webgl，异常时回退默认渲染 |
| 终端辅助 | fit、search、serialize 等；前后端锁定兼容版本和 Unicode 宽度配置 |
| 本地运行 | Node.js/TypeScript，node-pty，随安装包提供兼容运行时 |
| 本地状态 | @xterm/headless；SQLite 保存会话索引与事件，分段文件保存终端输出和快照 |
| 进程生命周期 | 当前用户 LaunchAgent；连接进程与 Session Host 分离，通过认证 IPC 连接 |
| 云端 | Node.js/TypeScript、Fastify、WebSocket 中继 |
| 云端存储 | PostgreSQL：账号关联、主机、授权、会话摘要及审计；不保存终端正文 |
| 登录 | 标准 OIDC 身份提供方；产品端会话 Cookie、主机独立凭据，不自建密码系统 |
| 传输 | V1 全部经云端中继，主机只发起出站连接，不要求端口映射 |

V1 先采用单区域中继，不承诺跨洲接近本机的回显延迟；中继重启必须触发重连而不能导致 Agent 退出。主机绑定、路由和协议字段保留扩展余地，但不预先建设复杂调度或插件市场。

### 4.2 进程持久性

浏览器关闭、云端故障、本地连接服务重启均不得结束 Session Host 中的会话。Session Host 自身退出、用户注销、系统重启则属于执行中断，后续进入历史恢复流程，不能承诺原 PTY 继续存在。

本地服务更新需等待无活动会话，或取得用户明确同意；不为升级直接杀死运行中的任务。提供可见的“任务运行时阻止空闲睡眠”设置，不能保证合盖、断电或用户强制睡眠时任务继续执行。

## 5. 会话、同步与操作权协议

### 5.1 身份分层

- accountId：产品账号。
- hostId：执行主机；不能只凭客户端自报身份建立关联。
- sessionId：产品中的稳定会话 ID。
- runtimeEpoch：每次重新启动 CLI 的运行世代；旧运行的输入、输出和 Hook 不得污染新运行。
- nativeSessionId：厂商原生会话 ID，与 Agent 类型共同解释。
- clientId：当前浏览器实例；不是用户身份的替代品。
- controlEpoch：当前操作权版本。
- outputSeq / eventSeq：终端输出与 Hook 事件各自的序号，不假定两条流存在共同精确顺序。

同一个产品会话可以有多个运行世代。CLI 内 /clear 或 /resume 切换原生会话时，记录原生 ID 绑定历史，并以权威生命周期事件更新当前绑定，不能一直使用首次捕获的 ID。

### 5.2 终端同步

输出用有序二进制数据帧传送；业务控制和 Hook 状态用类型化消息。协议至少覆盖 attach、snapshot、output、outputAck、claimControl、input、inputAck、resize、status 和 exit。

Session Host 连续消费 PTY 输出并维护 headless 状态。快照在已完成解析的序号处生成，同时记录终端行列、主/备用屏幕、光标及必要模式和解析边界信息。客户端从同一检查点恢复，之后只应用更高序号输出。

快照与增量的订阅必须原子衔接或带有缓存水位，避免初始化过程中漏输出。输出缺口在日志可用时补齐；缺口无法补齐则重新取快照，不能带着未知状态继续显示。

浏览器短暂掉线使用增量恢复；新浏览器或长时间离线先恢复当前快照，较早历史按需读取。快照不能在任意半条控制序列处简单截断；serialize 是组成部分，不是全部恢复协议。

终端协议查询由本地权威终端统一响应；显示副本的自动响应不作为用户键盘输入转发。客户端的剪贴板与链接动作单独授权。

### 5.3 操作权、尺寸和输入重试

每个会话同一时刻最多一个控制者。主机串行处理接管，递增 controlEpoch；任何 input、resize、interrupt 都必须携带当前版本并通过授权校验。旧控制者已经接受的输入先完成，之后才允许新控制者输入，不声称能撤回已交给 CLI 的字节。

当前操作端决定 PTY 行列。查看端不发 resize，按权威尺寸显示，必要时横向滚动。接管后等待稳定布局，再由主机确认尺寸变化，避免多端反复 SIGWINCH。

输入帧携带运行世代、操作权版本与输入序号。ACK 只表示主机接收/写入阶段，不表示 Agent 已理解或执行命令。活运行内做去重；运行世代变化或无法确认投递结果时，不自动重放未知输入，显示“输入是否送达无法确认，请检查终端”。

断网时禁用实时输入，保留未提交草稿；不自动积攒 Enter、审批选择或中断键并在恢复后重放。

## 6. Codex 与 Claude Code 适配

每个内置适配器负责：检测版本、构造启动/恢复参数、接入 Hook、捕获原生会话 ID、归一化事件、维护能力与版本清单。不负责重画 CLI、不改写模型请求、不替代厂商权限政策。

两者均在 PTY 中运行原生交互式 CLI。恢复使用精确 nativeSessionId，禁止用“最近会话”猜测目标。Codex 使用其 resume 能力，Claude Code 使用 --resume 指定会话。

Hook 优先通过厂商支持的会话级配置或受管插件加载。若所选版本只能通过持久配置注册，则安装时明确确认、备份并合并受管条目，卸载只移除本产品条目；不覆盖用户 Hook，不为隔离 Hook 随意替换厂商 HOME 或认证目录。

桥接仅在拥有本产品会话标识和短时运行凭据时上报；普通外部 CLI 会话不被收集。桥接先本地落入短小事件队列再返回，中继发送异步完成；明确超时，Hook 故障不阻塞用户 CLI，且不输出权限决定或额外提示内容。

### 6.1 状态模型

不要用一个字段混合网络、进程和 Agent 状态：

| 维度 | 示例 |
| --- | --- |
| 主机/连接 | 在线、离线、重连中 |
| 进程 | 启动中、运行中、已退出、恢复失败 |
| Agent 活动 | 工作中、等待审批、等待输入、本轮结束、未知 |
| 操作权 | 本设备、其他设备、无人操作 |

观察 SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、PermissionRequest、Stop 及厂商对应的补充事件。具体可用事件以兼容版本为准。主 Agent 与子 Agent 分开关联，子 Agent Stop 不得把父会话错误标为完成。

权限请求未确定结束时，不能被无关的并行工具事件清除。状态附带更新时间与可信来源；Hook 缺失、乱序或信号不足时显示未知/待确认，不按“几秒没有输出”推断完成。

原始输入流不能稳定判定用户对话轮数。V1 显示已确认的用户提交轮次/厂商 turn 映射，不展示虚假的完成百分比；不具备连续记录时隐藏累计轮数或明确仅统计本产品记录范围。

### 6.2 审批体验

V1 统一保留 CLI 原生人工审批。Hook 报告等待状态，工作台突出该会话，用户接管后直接操作 CLI。不中间截走审批，不自动批准，不为了方便开启 bypass/yolo 等模式。

“网页审批按钮”不属于 V1 范围；这是界面收敛，不是删除跨 PC 审批能力。PC B 仍可以在同一终端完成审批。

## 7. 恢复行为

| 故障 | V1 行为 |
| --- | --- |
| 刷新/关页/换 PC | 原进程继续；恢复屏幕并重新获取操作权 |
| 浏览器或主机短时断网 | 本地 Agent 在自身依赖可用时继续；显示离线，恢复后补齐 |
| 中继/连接进程重启 | Session Host 不受影响；重新鉴权与同步 |
| Agent 退出 | 保留记录，标记已退出；有原生 ID 时提供恢复入口 |
| Session Host 崩溃/系统重启 | 所有旧运行失效；不自动发送旧输入或继续任务 |
| 用户点击恢复 | 原主机、原目录、新 PTY，使用精确原生 ID 恢复并生成新 runtimeEpoch |
| 原生记录缺失/目录移除/凭据过期 | 明确显示原因，不静默新建会话冒充恢复成功 |

恢复后 CLI 根据自己的历史重新绘制界面。旧运行输出只读保留并显示恢复分界，不把旧画面当作新进程真实状态。工具外部副作用不会回滚，正在进行的网络请求、子进程也不会被历史恢复原样重建。

## 8. 账号、安全和数据边界

### 8.1 授权

云端所有主机与会话访问均验证 accountId -> hostId -> sessionId 归属；主机复核签名短期访问凭证，限定用途、会话、运行世代和有效期。WebSocket 建立时和操作期间都要验证，不只在登录页校验。

支持撤销浏览器登录、解绑主机。授权撤销及时推送到主机并关闭对应远程通道；丢失撤销推送时通过最长 30 秒的授权续期窗口失效。主机拒绝新的过期授权输入，但不因此杀死本地任务。

本地 Hook/IPC 接口做身份校验，不开放无鉴权 HTTP 端口。新建会话只允许已授权项目根目录中的规范化路径，并防止符号链接逃逸；这只是会话创建限制，不是对原生 Agent 的完整文件沙箱，工具权限仍按厂商策略执行。

### 8.2 传输与秘密

V1 明确采用可信云中继 + TLS/WSS，不声称端到端加密：中继转发时技术上能够接触明文终端内容，但不落盘正文或记录输入。E2EE 是后续可单独设计的增强，不应在产品说明中混淆。

主机身份凭据保存在 Keychain；厂商登录材料保留在厂商本地位置，产品不上传或集中托管。云端不主动收集项目正文，但终端内容可能包含源码或用户显示出的秘密，因此不能承诺“任何代码都不经过云端”。

终端页启用严格 CSP，不加载广告/会话录制脚本；日志不记录终端正文、输入、Hook 原始敏感参数或访问令牌。链接限制允许协议，OSC 52 剪贴板写入需用户许可。账号接管意味着远程终端控制风险，应支持 MFA/Passkey 的身份提供方策略。

### 8.3 保存与清理

完整终端日志、快照、厂商会话 ID 与 Hook 事件默认留在执行 Mac。云端保存最小会话摘要（标题、Agent、主机、时间、粗粒度状态）和无正文控制审计；项目绝对路径仅按需传输给已授权客户端，不纳入常规服务日志。

输出历史设置可配置保留期和磁盘配额，保留活动会话最新恢复快照；清理更早日志后显示历史范围已截断，不影响原生 CLI 会话文件。不得自动清理厂商历史。磁盘不足时停止宣称历史持久化正常，显示明确告警并按有界缓冲策略处理，不能无限增长内存。

## 9. 性能与验收

以下是待实现、待实测的验收目标，不是已验证指标。首轮实验固定 Mac 型号、显示刷新率、PC 浏览器版本、网络 RTT 与测试轨迹，并把这些条件纳入报告。

- 普通交互轨迹在 60Hz 显示器上以稳定 60fps 为目标；记录帧间隔 p95/p99 与超过 50ms 的长任务，不只汇报平均 FPS。
- 前端输入处理、主机转发、前端输出处理的应用附加延迟合计以 p95 <= 50ms 为目标；端到端回显另计网络 RTT 和 CLI 自身时间。
- 在 RTT <= 50ms、可用带宽 >= 20Mbps、恢复负载 <= 1MiB 的基准条件下，从连接 ready 到恢复当前屏幕以 p95 <= 1 秒为目标；历史正文延迟加载。
- 单主机 10 个混合 Agent 会话、至少两个 PC 客户端持续 30 分钟；一个输出密集会话和一个慢客户端不能让其他前台会话失去交互性，内存和队列必须受配置上限约束。
- 活动终端字节流直接写入终端实例，不经 React 状态树；输出有界合批、按解析进度 ACK、可见终端优先，后台终端按需卸载渲染并通过快照重建。
- 大流量与历史恢复必须与输入/接管控制采用独立队列和调度，限制每个数据帧尺寸，避免历史传输长时间阻塞控制消息。

必须通过的功能测试：

1. Codex/Claude Code 各完成新建 -> 输入 -> 多轮 -> 等待审批 -> PC B 接管 -> 审批 -> 完成的闭环。
2. PC A 关闭网页，原进程不退出；PC B 打开的 nativeSessionId 不改变。
3. 同账号可访问，其他账号即使猜到 ID 也不能读取快照、输出或发送输入。
4. 快速反复接管、同时接管、过期输入、迟到 resize，不造成双端写入。
5. 断网/中继重启/连接进程重启后，序号连续或明确重新同步，不乱码、不重复输入。
6. 原进程退出及主机重启后，用户确认恢复精确会话；找不到历史时明确失败。
7. 中文 IME、emoji、宽字符、多行粘贴、Tab、方向键、Esc、Ctrl+C、滚动和交互菜单均通过真机测试。
8. 控制序列跨帧截断、备用屏幕、终端查询、resize 交错、快照与增量竞态可恢复且不产生重复协议回复。
9. Hook 缺失/超时/子 Agent 事件、磁盘满、快照损坏、CLI 不兼容、WebGL 上下文丢失均有可解释的降级或失败。
10. 控制端撤销、主机解绑、凭证过期在授权窗口内阻断后续远程输入，不误杀本地 Agent。
